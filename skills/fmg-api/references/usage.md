# Attribution and recovery

Prefix actual work with `fmg --run-id RUN_ID`; use the same ID across pages, enrichment submission and sending. Query `fmg --run-id RUN_ID usage`. Omitted IDs are grouped as `unassigned`; a resumed enrichment job retains its original run. Another colleague's token cannot read your ledger.

The ledger records attempts, statuses, recognized resource counts and available numeric Gemini usage. `started` may mean a process stopped after an upstream request; it is not zero consumption. Missing result counts are not zero. Known YouTube successful-read quota estimates use the dated official quota reference returned with the summary; search-call buckets and other units are separate, not money. Failed/unrecognized calls remain unresolved. Rate-limit remaining is not billing balance.

## Required run accounting

Before the first metered request, discover the host tool named `get_usage_limits` (in Codex desktop typically `mcp__codex_app__get_usage_limits`) and call it if available. Save a sanitized snapshot as `codex-usage-before.json`: capture time, limit IDs/names, each window's usedPercent, windowDurationMins and resetsAt. Prefer rateLimitsByLimitId; fall back to rateLimits. Do not save account IDs, credentials or unrelated profile data. This is a host tool, not an fmg command. If absent/denied, record `unavailable` and the reason; continue the user's task. Never search private local sessions or call a reset/purchase tool to obtain usage.

At the end (also partial failure), call the tool again and save `codex-usage-after.json`, then save `fmg --run-id RUN_ID usage` as `usage.json`. Report each window separately: remaining = clamp(100 - usedPercent, 0, 100). Compare only matching limit ID, window name, duration, reset timestamp and account/session identity; if reset/account changed, before snapshot is missing, or usage decreased, mark the delta unavailable. A comparable change is **shared-account percentage points observed during the run**, NOT precise task consumption or dollars. Other tasks/devices may contribute and percentages are rounded. Preserve a missing window as unknown, not zero. When genuine task-specific measurements exist, report them separately with provenance.

## Provider costs

Run `fmg pricing` for offline, machine-readable service rules (no provider call or login required). It is guidance, not a balance lookup. On older clients without this command use the rules below; do not make a paid test just to learn prices.

- **YouTube:** estimate marginal API money as USD 0. Record daily project quota separately; exhaustion needs a reset or quota adjustment, not necessarily recharge.
- **Twitch:** standard Helix reads are estimated at USD 0 marginal API charge under current service assumptions, excluding hosting; this is not a billing balance or unlimited quota. Respect returned rate-limit headers and endpoint-specific caps. OAuth maintenance requests do not create research result rows and are not counted as creator reads. A 429 means wait for the indicated reset, not buy credits; invalid company authorization needs administrator repair. Counts and cost still appear in run usage.
- **Gemini/email enrichment:** use the returned cost snapshot: uncached input, cached input, output including thinking, and Google Search quantities multiplied by the dated model rates. Report the known amount even if one component is unknown. Shared free allowances and discounts are not deducted; the result is an estimate, not account debit.
- **X:** keep the provisional published-price estimate. It includes primary and expanded resources, but not cross-request daily billing deduplication. Account-specific unit-price calibration is pending; do not spend credits on calibration unless requested.
- **Steam:** current marginal API estimate is USD 0. **SMTP, subscriptions and hosting:** excluded unless separately measured; do not invent a zero invoice.

Version 0.2.0 attaches `meta.cost` to platform responses; completed Gemini enrichment checkpoints contain `cost`. The authoritative run ledger sums these persisted snapshots without repricing history. `estimated_cost` is the known USD subtotal; if `complete_cost_known` is false, also report `unpriced_request_count` and the missing components from `providers.*.cost_breakdown`. Do not discard a known subtotal merely because another service is unknown. `actual_cost` remains null without attributable billing. Never add per-call estimates to the ledger total (that double counts).

Estimates use the returned pricing version/source and list prices, before discounts, free allowances and X daily deduplication. X primary and expanded resources are counted by type; returned_items alone is not billable quantity. Gemini counts input, cached input, output including thinking, and reported Search queries; missing grounding metadata remains an unpriced component. YouTube/Steam zero marginal API charge excludes server costs/subscriptions, and YouTube quota is reported separately. Old runs retain unknown costs when no snapshot exists. Failed/started upstream outcomes can cost money even if no usable result exists.

End-of-task summary has four slots: (1) provider requests and status, (2) per-provider estimated USD plus known subtotal and exclusions, (3) Codex account before/after remaining and comparable percentage-point changes, or the concrete reason unavailable; precise task usage separately, (4) budget limits reached and artifact paths. Do not derive USD from Codex plan prices or remembered API prices.

Exit codes: 0 successful request (still inspect state), 2 input, 3 auth/scope, 4 quota/rate limit, 5 network/upstream/timeout, 6 failed email work, 7 unknown delivery, 130 cancellation. Configuration missing is different from invalid user credentials. On quota/balance failure stop new requests to that provider and retain work; do not recharge or raise limits. On a transient read failure, an explicit bounded retry can fit the remaining authorized budget. Never automatically retry mail delivery. Do not hide partial provider errors inside a success envelope.

If the provider explicitly reports insufficient funds/credits or disabled billing, pause that provider and ask the user in conversation to recharge or fix company billing. Preserve run/job IDs and successful work for resumption after confirmation; do not recreate completed jobs. Other services may continue only where independent and within the original request. A generic 429, 403, timeout, or unavailable service does **not** establish an empty balance: distinguish quota/rate limits, authorization and network failures. When ambiguous, explain the uncertainty and ask for the relevant account check instead of declaring that recharge is required. Never retry a known billing blockage repeatedly.
