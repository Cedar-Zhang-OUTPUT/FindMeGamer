# Creator analysis repair — 7 September 2026

Scope: the company-internal Demo's two observed Creator failures. No client
changes, new infrastructure, SMTP activity, or unrelated Creator reanalysis.

## Diagnosis and changes

- CoryxKenshin had 12 successful checkpoints, but the final Brief's positioning
  exceeded the 144-character contract. The full-response repair remained invalid.
  Explicit character targets now leave headroom; only overlong Brief strings can
  receive a bounded, small semantic rewrite. Evidence, contacts and other fields
  are not regenerated by that repair. Original schema and evidence/contact
  binding remain mandatory. No truncation, claim deletion or relaxed limits.
- jacksepticeye's image input reached DeepSeek; the returned visual JSON failed
  validation. Re-fetching the same 12 images through the server's safe loader
  succeeded. The visual evidence catalog incorrectly allowed `ai_inference`
  while the visual schema required `visual_observation`. Creator visual v2 fixes
  this conflict and explicitly describes availability, null reasons and trimmed
  text. Historical response JSON was not retained, so individual historical root
  validator failures cannot all be reconstructed. New logs expose only fixed,
  code-owned reason codes, never model payloads or credentials.
- The maintenance recovery CLI creates a new Job and copies valid checkpoints in
  one transaction before dispatch. It preserves terminal history and publishes
  through the normal transaction. Visual recovery also recomputes presentation
  and Brief, which depend on the visual result.
