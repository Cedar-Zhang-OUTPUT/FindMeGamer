# One-click Creator Search — internal Demo

## Boundary

Only explicit `POST /api/v2/activities/{id}/creator-searches` starts this flow.
Existing discovery, including the user's 68-candidate activity, is not enrolled.
No SMTP is invoked. Email completeness is independent of match fit.

The server runs planning → bounded discovery → freezes all candidates in this
batch → Profile enrichment → public-contact enrichment → existing progressive
screening / Deep Match / ranking. It does not depend on a client's loaded page.
Usable analyzed Profiles and their public emails are reused. YouTube analysis's
successful contact checkpoint is reused; other missing contacts use bounded
public-page parsing followed by the existing Gemini research gateway.

Creator enrichment concurrency is two; existing analysis pipelines retain their
internal bounds. Successful units and evaluation steps persist across explicit
retries. Stop lets the current bounded wave finish but starts no next wave;
successful Profile updates and Match Briefs remain. Append creates an independent
scope excluding every candidate already in the query, without changing prior results.

An existing externally owned analysis job is not executed a second time. The unit
reports `search_profile_busy`; retry after that job completes reuses its Profile.
Expired search execution and unknown evaluation outcomes require explicit cost
acknowledgement. No implicit paid replay is triggered by duplicate broker delivery.

## Client contract

Exact schemas: `backend/app/schemas/creator_search.py`.
Create, stop, retry and append require `Idempotency-Key`. Queue dispatch failure
means the receipt is already saved: retry with the **same** key.

- History: `GET /api/v2/activities/{id}/creator-searches`.
- Progress: `GET /api/v2/creator-searches/{id}`.
- Per-Creator progress: `GET /api/v2/creator-searches/{id}/creators`.
- Commands: `POST /api/v2/creator-searches/{id}/{stop|retry|append}`.
- Commands return `{search_id,status}`; retry body supports `acknowledge_unknown`.
- History and Creator pages: default 50, maximum 200; offset pagination.
- `profile_ready` includes `profile_reused`; do not add the latter a second time.
- Poll search, not query, to its terminal state; read all Creator and evaluation
  result pages using `evaluation_id`. Zero matches can still be completed.
- `partial` preserves usable results and per-unit errors. Button eligibility comes
  from `retryable` and `outcome_unknown`, not parsing an error message.
- Errors remain nullable strings with a generic unknown-code fallback.

Command errors: `search_running`, `search_not_retryable`, `search_outcome_unknown`,
`search_not_found`, `search_queue_unavailable`, plus shared `discovery_not_found`,
`request_invalid` and `idempotency_key_conflict`.

Task errors: `search_planning_failed`, `search_discovery_incomplete`,
`search_discovery_partial`, `search_outcome_unknown`, `search_no_usable_profiles`,
`search_failed`. Creator errors: `search_identity_changed`,
`search_platform_unavailable`, `search_profile_busy`, `search_profile_unusable`,
`search_profile_failed`, `search_email_configuration_missing`, `search_email_failed`.
